# Project Blood

## 项目概述

**Project Blood** 是一款基于Unity引擎开发的2D俯视视角射击Roguelike游戏。玩家扮演一名拥有特殊血液能力的船员，在随机生成的地牢中战斗，收集资源强化武器和自身，击败敌人并挑战Boss。

- **项目类型**：2D俯视射击Roguelike游戏
- **核心玩法**：随机地牢探索、多武器切换战斗、血液资源循环系统
- **开发周期**：2025年11月至今
- **开发人数**：1人

## 核心亮点

1. **数据驱动的三层继承武器架构:** 分层抽象武器通用逻辑，仅通过配置参数即可快速新增枪械，大幅降低扩展成本。
2. **数据驱动的敌人设计体系:** 统一敌人伤害接口，所有敌人攻击模式参数可在面板直接调整，可快速扩展敌人类型。
3. **基于难度评级的敌人生成系统:** 按照关卡难度分数动态匹配敌人强度与波次，全程维持平滑递增的战斗压力。
4. **战斗资源闭环系统:** 血库管理玩家的脏血资源，对武器弹药量做软性限制，失去的生命值转换为血库资源，脏血装填的武器击杀生成纯血回复生命值，实现“消耗生命值获取脏血 - 射击消耗脏血 - 击杀回复生命值”的闭环；
5. **基于BFS加权随机程序化地牢:** 动态网格驱动随机房间布局，自动生成连通通道与房间解锁逻辑，支撑Roguelike随机探索玩法。

## 代码组织与系统交互

<br />

项目代码按功能职责自然拆分，核心系统基于面向对象思想做了抽象与逻辑复用

#### 整体分层逻辑

大致分为四个层级，边界非严格定义，以实际开发效率优先：

1. **引擎基础层**：基于 Unity 2D 原生能力，使用 Physics2D 做碰撞检测、Tilemap 搭建地图、协程处理异步逻辑、SceneManager 实现异步场景加载
2. **框架支撑层**：基于 QFramework 搭建基础设施
   - 使用 UIKit 管理各 UI 界面，AudioKit 统一管理全局音效播放和音效密度
   - 业务物体、UI 面板脚本统一继承 ViewController 基类(基于MonoBehavior)，配合 Bind / OtherBind 组件与代码生成工具，自动完成子对象、UI 控件、音频资源的引用绑定，提供标准化对象初始化生命周期
   - 通过 BindableProperty 实现响应式数据绑定，UI 数值随状态自动更新，无需手动刷新
3. **业务逻辑层**：按玩法功能拆分为玩家、武器、敌人、地图、掉落、特效等独立类，承载全部战斗与关卡逻辑
4. **数据与状态层**：通过全局静态类统一管理运行时状态（血量、金币、难度、暂停），使用 PlayerPrefs 实现局外成长属性的本地持久化存储

#### 核心系统抽象设计

- **武器系统**：以`WeaponBase`为基类封装通用射击、换弹、弹药管理逻辑，按射击模式派生出全自动、半自动两类子类；具体武器仅需配置伤害、射速、弹匣等参数即可扩展，同时以组件形式实现吸血、血库强化等附加特性。
- **敌人系统**：以`Enemy`基类统一移动、受伤、死亡的通用流程，不同攻击模式的敌人继承基类实现差异化行为；敌人行为通过有限状态机实现追击、游走、攻击的切换；配套简单工厂类，根据关卡难度分数生成对应强度的敌人组合。
- **地图系统**：基于预定义关卡拓扑 + BFS 算法 + QFramework DynaGrid 动态网格，实现**加权随机**的程序化地牢生成；自动完成房间布局、通道连接与房门生成，动态控制房间战斗解锁与门状态切换。

#### 核心交互流程

1. 玩家输入驱动角色移动与瞄准，调用武器基类接口触发射击逻辑
2. 子弹命中敌人后调用统一受伤接口结算伤害，同步触发特效播放、掉落物生成、血液资源结算
3. 全局状态变更通过响应式绑定自动同步至 UI 界面，保证数据与显示一致
4. 地牢生成完成后，关卡系统根据当前地牢配置初始化难度分数，驱动\`EnemyFactory\`生成对应强度的敌人波次；房间战斗完成后，联动地图系统解锁下一个房间与通道。

> 说明：当前为个人项目迭代状态，部分全局类职责仍有冗余，存在少量重复代码，部分结构有进一步优化空间。
