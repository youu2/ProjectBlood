# 核心系统设计文档

# *1.敌人系统*

### 1. 系统架构与职责划分

敌人系统采用「接口契约 + 模板方法基类 + 攻击方式派生」的三层架构：

```
敌人系统架构
├── IDamageable (接口)      ── 统一伤害契约，兼容未来陷阱/中立单位
├── Enemy (抽象基类)         ── 状态机骨架 + 移动/朝向/受伤/死亡通用逻辑
│   ├── MeleeEnemy          ── 近战型：攻击距离内直接造成伤害
│   ├── ShootingEnemy       ── 弹丸型：散射弹丸 + 连射协程
│   └── LaserEnemy          ── 激光型：充能散射激光 + 持续高频伤害
├── EnemyFactory (单例)     ── 预制体集中托管，按难度评分创建
└── EnemyBullet             ── 子弹实体（触发器碰撞 + 自销毁）
```

数据流向：`EnemySpawner → EnemyFactory.EnemyByScore → 实例化 Enemy 子类 → Room.GetEnemies().Add → 状态机驱动行为 → 死亡时 Room 列表移除并通知 Global 计数`。FxManager 集中处理血迹/尸体/受击特效，与敌人系统解耦。

### 2. 核心接口与基类定义

`IDamageable` 接口定义伤害契约，所有可对玩家造成伤害的实体统一实现：

```csharp
public interface IDamageable {
    Room Room { get; set; }              // 所属房间引用（用于死亡清理）
    GameObject GameObject { get; }
    float HitDamage { get; }             // 直接伤害值
    void TakeDamage(float damage, Vector2 HitDir);
    float CurrentHealth { get; }
    float MaxHealth { get; }             // 用于吸血比例换算
}
```

`Enemy` 基类继承 `ViewController` 并实现 `IDamageable`，核心字段包括 `moveSpeed`、`currentHealth`、`direction`、`attackRange` / `chaseRange`（控制状态切换的双距离阈值）、`body`（SpriteRenderer，用于死亡生成尸体）。关键虚方法：`UpdateChase/UpdateWander/UpdateFire`（状态行为模板）、`StartFire/StartWander`（状态进入钩子）、`MakeDamage`（伤害落地）、`Death`（死亡统一处理）。子类仅需重写需要的钩子即可注入差异化行为。

### 3. 状态机具体实现形态

采用「枚举驱动 + switch 分发 + 模板方法」的轻量级 FSM，避免引入 QFramework FSMKit 的额外开销。状态定义：`Idle / Chase / Wander / Fire`。

转换条件（基于双距离阈值）：

- **Chase → Wander**：`distanceToPlayer ≤ chaseRange`（进入交火区）
- **Wander → Fire**：`currentWanderTime ≥ WanderDuration`（侧向游走蓄势）
- **Wander/Fire → Chase**：`distanceToPlayer > attackRange`（目标逃离）
- **Fire → Wander/Chase**：攻击协程结束（由子类决定回到哪个状态）

`attackRange` 严格大于 `chaseRange`，确保敌人在 Wander 期间不会因自身位移自动脱离攻击范围。状态机在 `Update()` 中通过 `switch` 分发，所有状态共享 `direction`、`UpdateRotate` 等基础计算。Player 为 null 时强制回退到 Idle，避免对销毁对象的访问。

### 4. 基层通用逻辑实现

**巡逻机制**：`StartWander()` 计算与玩家方向的垂直向量 `perpendicular = (-direction.y, direction.x)`，随机取正/负作为 `wanderDirection`，使敌人围绕玩家做切向游走而非直线逼近，给玩家反应窗口。

**追击算法**：`GetDirectionToPlayer()` 返回归一化方向向量，每帧 `transform.position += direction * moveSpeed * Time.deltaTime`，无寻路依赖（房间内无障碍）。`UpdateRotate` 支持 flipX 翻转或 Z 轴 LerpAngle 插值两种朝向模式，由 `useFlipSprite` 切换。

**攻击流程**：基类 `MakeDamage()` 调用 `Player.player1.TakeDamage(HitDamage)`；`TakeDamage` 触发音效 + 受击特效 + 血量扣减，归零时调用 `Death`，统一完成掉落生成、Room 列表清理、尸体生成、全局计数减一、对象销毁。

### 5. 按攻击方式分类的差异化设计

| 类型                | 攻击判定                                              | 伤害类型     | 状态流转特殊点                                                |
| ----------------- | ------------------------------------------------- | -------- | ------------------------------------------------------ |
| **MeleeEnemy**    | Fire 状态进入瞬间直接 `MakeDamage`                        | 单次接触伤害   | 1 秒后回到 Chase（无 Wander 中转）                              |
| **ShootingEnemy** | 协程发射散射弹丸，子弹 `OnTriggerEnter2D` 判定                 | 弹丸伤害     | 连射 `totalBurstCount × shotsPerBurst` 后回到 Wander        |
| **LaserEnemy**    | LineRenderer + Raycast2D，按 `damageFrequency` 高频判定 | 持续检测造成伤害 | 充能(预警)→开火→淡出，结束后直接回 Chase（激光型只用chaseRange控交火距离，伤害距离较远） |

散射弹丸方向通过旋转矩阵计算：`baseDirection` 旋转 `-scatterAngle/2 ~ +scatterAngle/2` 区间角度，支持均匀分布与随机分布。激光敌人支持多激光（`laserCount` + `spreadAngle`），用墙层 Raycast 截断激光路径，避免穿墙。

### 6. 新增敌人类型，以及现有类型的复用效率

**新增敌人类型**：① 继承 `Enemy` 或已有攻击型基类；② 在 Inspector 配置 `moveSpeed / chaseRange / attackRange / WanderDuration` 等参数；③ 重写 `StartFire / UpdateFire`（如需新攻击形态）或直接复用协程。基类已封装移动、朝向、受伤、死亡、房间清理等全部通用逻辑，子类仅关心攻击形态本身，但是面对复合型攻击模式的敌人会难以复用代码。

**同类敌人复用性**：新增同类型敌人只需敌人脚本组件 + 改数值(Sprite, 音效)，零代码。`EnemyFactory.EnemyByScore` 维护预制体和难度分数映射，新增敌人只需注册一个难度分数映射。架构以 \[ 配置化优先、继承为辅 ] 的方式，将单种新敌人的开发成本压缩至分钟级，而且调试效果直观。

# 2. 武器系统

&#x20;

### 1. 系统概述与架构分层

武器系统的核心设计目标是通过参数化配置实现零代码快速生成变种武器，同时保持攻击逻辑的分层复用与状态一致性，适配多武器无缝切换的核心玩法。

系统基于 QFramework 架构规范开发，`WeaponBase`继承自表现层基类`ViewController`，整体分为三层结构：

> 现修改为MonoBehavior，因为武器重构为数据驱动，单个`ViewController`脚本无法对应多个武器，代码生成和组件绑定工具失效，转为手动绑定

plaintext

```
武器系统核心层
└── WeaponBase (抽象基类)
    ├── 内部持有组件
    │   ├── GunClip：弹药状态机 + 数据管理
    │   └── AttackIntervalFeature：帧率无关的攻击间隔控制
    ├── AutomaticWeapon (全自动武器子类)
    │   └── Laser：射线检测型激光武器
    └── SemiAutomaticWeapon (半自动武器子类)
        └── ShotGun：多弹丸散射霰弹枪

外部依赖系统
├── BloodBank：全局血库资源系统
├── AudioKitManager：全局音频管理
└── CameraUtils：相机震动工具

```

数据执行流向：`玩家输入 → WeaponBase.KeepAttacking() 入口 → 攻击间隔校验 → 弹药状态校验 → Attack() 生成子弹并注入伤害属性 → 调用音频/相机工具播放表现 → 扣减弹药状态`。换弹流程中通过`BloodBank`接口消耗脏血资源并标记弹夹强化状态，武器系统不直接修改血库内部数据。武器与音频系统通过统一管理器入口调用，实现了音频播放逻辑与武器业务逻辑的职责分离，武器侧不持有任何`AudioSource`组件引用。

### 2. 核心基类与接口定义

**WeaponBase** 抽象基类，承载全武器通用逻辑。核心属性包括：`MaxAmmo`（弹匣容量）、`AttackInterval`（攻击间隔）、`ReloadTime`（换弹时长）、`spreadAngle`（子弹散布角度）、`BloodRequired`（单次换弹血液消耗）、`IsBulletEnhanced`（当前弹夹强化状态）。核心方法：

- `Attack(Vector2 shootDir)`：子弹生成、属性注入与表现触发的统一入口
- `KeepAttacking(Vector2 shootDir)`：攻击主循环，包含间隔校验、空仓处理与状态更新
- `Reload()`：常规换弹协程启动入口
- `SwitchFromSet() / SwitchToSet()`：切枪时的状态重置与初始化

**GunClip** 纯数据状态组件，独立封装弹药与换弹状态机，不包含计时逻辑。核心方法：`CanShoot()`（射击前置校验）、`CanReload()`（换弹前置校验）、`StartReload / FinishReload / CancelReload()`（换弹状态流转）、`UpdateClipUI()`（弹药 UI 同步）。

**AttackIntervalFeature** 工具组件，通过`Time.time`时间戳比对实现帧率无关的攻击频率控制，与武器主逻辑解耦，可复用于其他需要频率控制的实体。

#### 逻辑分层规则

- **下沉至基类的统一逻辑**：攻击间隔校验、空仓处理、换弹协程调度、血库资源联动、切枪状态重置、子弹强化。所有同类型武器共享主循环逻辑，避免重复实现。
- **保留在子类的差异化逻辑**：全自动武器的循环音效启停（`StartAttacking / StopAttacking`）、半自动武器的单发射击音效、霰弹枪的多弹丸生成逻辑、激光武器的射线检测逻辑。

#### 参数化配置实现

通过`[SerializeField]`暴露 Inspector 可配置字段，实现同类型武器的零代码变种生成。

- 战斗数值：弹容量、射速、换弹速度、散布角度、弹丸数量、血液消耗
- 表现参数：镜头震动强度 / 时长、各类音效音量、动画触发器名称
- 基类字段覆盖绝大多数武器的通用配置，极少数特殊武器存在的冗余字段在继承架构下属于可接受范围。

### 3. 关键流程实现原理

#### 射击触发与执行全流程

1. 玩家按住开火键 → 全自动武器调用`StartAttacking()`，播放首发音效并启动循环音效，标记射击状态；
2. 每帧执行`KeepAttacking(shootDir)`主循环：先通过`attackInterval.CanAttack()`校验时间间隔，再通过`gunClip.CanShoot()`校验弹药与换弹状态；双条件满足时调用`Attack()`生成子弹（应用散布角度、应用强化伤害、触发枪口特效、镜头震动与动画），随后记录攻击时间戳、扣减弹药；
3. 弹药耗尽时：自动停止循环音效，标记新弹夹状态；首次空仓播放提示音效并弹出换弹提示。
4. 玩家松开开火键 → 调用`StopAttacking()`停止循环音效，播放尾音（仅在实际射击过的情况下触发）。

**边界场景设计**：切枪时通过`SwitchFromSet()`重置攻击间隔、终止换弹协程、清空提示状态，保障切枪操作的即时响应性，贴合无缝切枪的核心玩法；按住开火键期间完成换弹后，自动重新启动射击循环，无需玩家重新按键。

#### 常规换弹与脏血资源联动流程

1. 玩家触发换弹输入 → `Reload()`方法校验`gunClip.CanReload()`（非换弹中且弹匣未满）；
2. 启动换弹协程：调用`gunClip.StartReload()`标记换中状态，播放换弹音效；
3. 等待`ReloadTime`时长后，执行换弹完成逻辑：
   - `gunClip.FinishReload()`补满弹匣弹药；
   - 校验血库当前血量是否大于等于本次消耗，满足则标记弹夹为强化状态并扣除对应脏血；不满足则保持普通状态，子弹伤害按基础倍率衰减；
   - 子弹生成时直接写入最终伤害倍率，飞行过程中状态不受后续武器状态影响。
4. 换弹期间开火输入会被`CanShoot()`拦截，不触发射击。

### 4. 关键代码片段

1\. 基类通用攻击模板方法（`WeaponBase.cs`）

```C#
public virtual void Attack(Vector2 shootDir)
{
    Vector2 finalDir = ApplySpread(shootDir);
    Quaternion rotation = Quaternion.FromToRotation(Vector2.right, finalDir.normalized);
    
    PlayerBullet bullet = Instantiate(bulletPrefab, muzzlePoint.position, rotation)
        .GetComponent<PlayerBullet>();
    bullet.direction = finalDir;
    bullet.gameObject.SetActive(true);

    ApplyLifestealToBullet(bullet);
    fireFlash.Flash(muzzlePoint.position, shootDir);
    
    CameraUtils.ShakeMainCamera(CameraShakeIntensity, CameraShakeDuration);
    WeaponAnimator.SetTrigger(shootAnimTrigger);
}

```

**设计说明**：基类封装全武器通用的攻击主干流程，子类仅需重写该方法即可实现差异化扩展（如霰弹枪循环生成多颗弹丸、激光武器替换为射线检测）。通用逻辑下沉、差异化逻辑开放，是参数化快速生成变种武器的核心支撑。

### 2. 特殊换弹机制实现（`WeaponManager.cs`）

```C#
private IEnumerator SpecialReloadCoroutine()
{
    yield return new WaitForSeconds(specialReloadDelay);
    
    if (isSpecialReloadTriggered 
        && bloodBank != null 
        && bloodBank.CurrentBloodAmount >= specialReloadBloodCost)
    {
        bloodBank.RemoveBlood(specialReloadBloodCost);
        
        foreach (var weapon in weapons)
        {
            if (weapon != null && weapon != currentWeapon)
            {
                weapon.FillClipDirectly();
            }
        }
        AudioKitManager.Instance.PlayOneShot("SpecialReload", SpecialReloadVolume);
    }

    GameUI.UpdateClipText(currentWeapon.GetGunClip());
    isSpecialReloadTriggered = false;
    specialReloadCoroutine = null;
}

```

**设计说明**：通过标记位实现 “攻击软中断”，蓄力过程不阻塞当前武器操作，等待结束后统一校验状态与资源，完成批量补弹。以低于逐把换弹的总成本激励玩家多武器轮换，是贴合无缝切枪核心玩法的专属机制。
