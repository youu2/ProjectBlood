# 核心系统设计文档

## 敌人系统

### 1. 系统架构与职责划分

敌人系统采用「接口契约 + 模板方法基类 + 攻击方式派生」的三层架构：

```
敌人系统架构
├── IDamageable (接口)      ── 统一伤害契约，兼容未来陷阱/中立单位
├── Enemy (抽象基类)         ── 状态机骨架 + 移动/朝向/受伤/死亡通用逻辑
│   ├── MeleeEnemy          ── 近战型：攻击距离内直接造成伤害
│   ├── ShootingEnemy       ── 弹丸型：散射弹丸 + 连射协程
│   └── LaserEnemy          ── 激光型：充能散射激光 + 持续高频伤害
├── EnemyFactory (单例)     ── 预制体集中托管，按难度评分创建
└── EnemyBullet             ── 子弹实体（触发器碰撞 + 自销毁）
```

数据流向：`EnemySpawner → EnemyFactory.EnemyByScore → 实例化 Enemy 子类 → Room.GetEnemies().Add → 状态机驱动行为 → 死亡时 Room 列表移除并通知 Global 计数`。FxManager 集中处理血迹/尸体/受击特效，与敌人系统解耦。

### 2. 核心接口与基类定义

`IDamageable` 接口定义伤害契约，所有可对玩家造成伤害的实体统一实现：

```csharp
public interface IDamageable {
    Room Room { get; set; }              // 所属房间引用（用于死亡清理）
    GameObject GameObject { get; }
    float HitDamage { get; }             // 直接伤害值
    void TakeDamage(float damage, Vector2 HitDir);
    float CurrentHealth { get; }
    float MaxHealth { get; }             // 用于吸血比例换算
}
```

`Enemy` 基类继承 `ViewController` 并实现 `IDamageable`，核心字段包括 `moveSpeed`、`currentHealth`、`direction`、`attackRange` / `chaseRange`（控制状态切换的双距离阈值）、`body`（SpriteRenderer，用于死亡生成尸体）。关键虚方法：`UpdateChase/UpdateWander/UpdateFire`（状态行为模板）、`StartFire/StartWander`（状态进入钩子）、`MakeDamage`（伤害落地）、`Death`（死亡统一处理）。子类仅需重写需要的钩子即可注入差异化行为。

### 3. 状态机具体实现形态

采用「枚举驱动 + switch 分发 + 模板方法」的轻量级 FSM，避免引入 QFramework FSMKit 的额外开销。状态定义：`Idle / Chase / Wander / Fire`。

转换条件（基于双距离阈值）：

- **Chase → Wander**：`distanceToPlayer ≤ chaseRange`（进入交火区）
- **Wander → Fire**：`currentWanderTime ≥ WanderDuration`（侧向游走蓄势）
- **Wander/Fire → Chase**：`distanceToPlayer > attackRange`（目标逃离）
- **Fire → Wander/Chase**：攻击协程结束（由子类决定回到哪个状态）

`attackRange` 严格大于 `chaseRange`，确保敌人在 Wander 期间不会因自身位移自动脱离攻击范围。状态机在 `Update()` 中通过 `switch` 分发，所有状态共享 `direction`、`UpdateRotate` 等基础计算。Player 为 null 时强制回退到 Idle，避免对销毁对象的访问。

### 4. 基层通用逻辑实现

**巡逻机制**：`StartWander()` 计算与玩家方向的垂直向量 `perpendicular = (-direction.y, direction.x)`，随机取正/负作为 `wanderDirection`，使敌人围绕玩家做切向游走而非直线逼近，给玩家反应窗口。

**追击算法**：`GetDirectionToPlayer()` 返回归一化方向向量，每帧 `transform.position += direction * moveSpeed * Time.deltaTime`，无寻路依赖（房间内无障碍）。`UpdateRotate` 支持 flipX 翻转或 Z 轴 LerpAngle 插值两种朝向模式，由 `useFlipSprite` 切换。

**攻击流程**：基类 `MakeDamage()` 调用 `Player.player1.TakeDamage(HitDamage)`；`TakeDamage` 触发音效 + 受击特效 + 血量扣减，归零时调用 `Death`，统一完成掉落生成、Room 列表清理、尸体生成、全局计数减一、对象销毁。

### 5. 按攻击方式分类的差异化设计

| 类型                | 攻击判定                                              | 伤害类型     | 状态流转特殊点                                                |
| ----------------- | ------------------------------------------------- | -------- | ------------------------------------------------------ |
| **MeleeEnemy**    | Fire 状态进入瞬间直接 `MakeDamage`                        | 单次接触伤害   | 1 秒后回到 Chase（无 Wander 中转）                              |
| **ShootingEnemy** | 协程发射散射弹丸，子弹 `OnTriggerEnter2D` 判定                 | 弹丸伤害     | 连射 `totalBurstCount × shotsPerBurst` 后回到 Wander        |
| **LaserEnemy**    | LineRenderer + Raycast2D，按 `damageFrequency` 高频判定 | 持续检测造成伤害 | 充能(预警)→开火→淡出，结束后直接回 Chase（激光型只用chaseRange控交火距离，伤害距离较远） |

散射弹丸方向通过旋转矩阵计算：`baseDirection` 旋转 `-scatterAngle/2 ~ +scatterAngle/2` 区间角度，支持均匀分布与随机分布。激光敌人支持多激光（`laserCount` + `spreadAngle`），用墙层 Raycast 截断激光路径，避免穿墙。

### 6. 新增敌人类型，以及现有类型的复用效率

**新增敌人类型**：① 继承 `Enemy` 或已有攻击型基类；② 在 Inspector 配置 `moveSpeed / chaseRange / attackRange / WanderDuration` 等参数；③ 重写 `StartFire / UpdateFire`（如需新攻击形态）或直接复用协程。基类已封装移动、朝向、受伤、死亡、房间清理等全部通用逻辑，子类仅关心攻击形态本身，但是面对复合型攻击模式的敌人会难以复用代码。

**同类敌人复用性**：新增同类型敌人只需敌人脚本组件 + 改数值(Sprite, 音效)，零代码。`EnemyFactory.EnemyByScore` 维护预制体和难度分数映射，新增敌人只需注册一个难度分数映射。架构以 \[ 配置化优先、继承为辅 ] 的方式，将单种新敌人的开发成本压缩至分钟级，而且调试效果直观。
