## 1. 小地图系统

### 1.1 功能概述

提供游戏世界可视化导航，实时显示玩家位置、已发现房间及状态连接。

### 1.2 核心配置

| 参数         | 默认值 | 设计意图             |
| ---------- | --- | ---------------- |
| `mapRange` | 2   | 控制视野范围，平衡信息展示与性能 |

### 1.3 房间状态

| 状态                             | 说明     | 视觉反馈   |
| ------------------------------ | ------ | ------ |
| `Unknown`                      | 未发现区域  | 隐藏     |
| `Init`                         | 已发现未进入 | 显示初始背景 |
| `Battle` / `Finished` / `Idle` | 已进入房间  | 当前房间高亮 |

### 1.4 核心逻辑

- **渲染机制**：每帧重建玩家周围 `mapRange` 范围内的已发现房间
- **发现机制**：进入房间时自动发现相邻有门连接的房间

> 设计决策详见：[核心决策文档](file:///e:/unity/project/ProjectBlood/Technical%20Documentation/核心决策.md)

## 2. 地图生成系统

### 2.1 功能概述

程序化生成关卡布局，包括房间节点树构建、BFS遍历生成、动态门布局及房间实例化。

### 2.2 核心数据结构

| 结构                   | 用途      | 关键字段                                     |
| -------------------- | ------- | ---------------------------------------- |
| `RoomNode`           | 定义关卡结构树 | 房间类型、子节点列表                               |
| `RoomGenerateConfig` | 存储生成配置  | `roomPosX`, `roomPosY`, `doorDirections` |
| `DynaGrid<T>`        | 动态网格容器  | 二维坐标索引                                   |

### 2.3 生成流程

1. **构建节点树**：定义关卡结构（初始房间→普通房间→宝箱/Boss房间）
2. **BFS遍历**：广度优先搜索生成房间位置
3. **预测权重优化**：避免生成死路，提高地图连通性
4. **房间实例化**：根据配置生成实际房间对象
5. **走廊生成**：连接相邻房间

### 2.4 BFS算法核心

使用队列存储待生成房间，通过预测权重机制选择扩展方向，平衡随机性与连通性。

### 2.5 与其他模块交互

| 模块    | 交互方式     |
| ----- | -------- |
| 玩家系统  | 设置初始房间位置 |
| 敌人系统  | 传递敌人生成配置 |
| 小地图系统 | 获取房间网格数据 |

> 架构设计详见：[PB 架构设计文档](file:///e:/unity/project/ProjectBlood/Technical%20Documentation/PB%20架构设计文档.md) 第3章「设计3：程序化地图生成」

## 3. 武器吸血系统

### 3.1 功能概述

武器造成伤害时按比例吸血，通过生成纯血道具的方式恢复生命值，支持等级升级机制。

### 3.2 核心参数

| 参数                     | 默认值 | 设计意图   |
| ---------------------- | --- | ------ |
| `BaseLifestealPercent` | 1%  | 基础吸血比例 |

### 3.3 机制流程

攻击 → 子弹携带吸血属性 → 击杀敌人 → 计算吸血总量 → 生成纯血道具 → 玩家拾取回血

### 3.4 关键设计

- **子弹携带**：吸血属性通过子弹传递
- **道具化表现**：吸血效果以纯血道具形式呈现，增强视觉反馈和操作手感

## 4. 护盾系统

### 4.1 功能概述

提供临时伤害抵挡能力，包含保护期机制（不消耗格挡次数）和格挡次数限制。

### 4.2 核心参数

| 参数                    | 默认值 | 设计意图     |
| --------------------- | --- | -------- |
| `initialBlockCount`   | 5次  | 基础格挡能力   |
| `gracePeriodDuration` | 5秒  | 激活后无敌缓冲期 |

### 4.3 机制流程

**伤害处理**：承受伤害 → 扣除格挡次数 → 保护期内不检查碎裂 → 次数耗尽且非保护期时碎裂

### 5.2 掉落物类型

## 7. 纯净之血系统（Pure Blood）

### 7.1 功能概述

武器吸血击杀敌人时，会从敌人身上爆出纯血道具，玩家拾取后恢复生命值。

### 7.2 核心参数

| 参数               | 默认值   | 设计意图             |
| ---------------- | ----- | ---------------- |
| `ejectSpeed`     | 7.5   | 初始飞射速度，实现吸血的视觉提示 |
| `flyDuration`    | 0.15秒 | 飞射阶段持续时间         |
| `chaseSpeed`     | 16    | 追踪阶段速度，保证能追上玩家   |
| `turnSmoothness` | 7     | 转向平滑度，太大会不自然     |

### 7.3 两阶段运动机制

**飞射阶段（Flying）**：

- 从敌人位置向随机方向弹出
- 带阻尼减速，模拟惯性效果
- 持续 0.15 秒后进入追踪阶段

**追踪阶段（Chasing）**：

- 平滑转向追踪玩家
- 速度逐渐加快到目标速度
- 碰到玩家就触发拾取

### 7.4 生成规则

- **触发条件**：武器吸血击杀敌人时生成
- **总治疗量** = 敌人总生命值 × 武器吸血百分比
- **数量计算**：1 + floor(总治疗量 / 5)，治疗量越大爆的血球越多
- **单个治疗量** = 总治疗量 / 数量，保证总和等于原吸血量

### 7.5 关键设计

- **视觉反馈**：多个小血球飞散再聚拢，比直接加血更有爽快感
- **独立音效**：有专门的拾取音效

> 详细设计见：[核心决策文档](file:///e:/unity/project/ProjectBlood/Technical%20Documentation/核心决策.md) 第5章「纯血道具系统设计」

## 8. 商店系统

### 8.1 功能概述

玩家可以在商店用金币购买道具，每个商店随机出售一件商品。

### 8.2 商品价格表

| 道具              | 价格    | 说明             |
| --------------- | ----- | -------------- |
| 纯血（Pure Blood）  | 1 金币  | 最便宜的回血道具       |
| 脏血（Dirty Blood） | 5 金币  | 补充 30 点血库容量    |
| 护盾（Shield）      | 10 金币 | 5 次格挡 + 5 秒保护期 |

### 8.3 购买流程

1. 玩家靠近商店 → 显示价格提示
2. 按 F 键购买
3. 检查金币是否足够
   - 足够：扣除金币 → 生成道具 → 商品售罄
   - 不足：显示"Too expensive..."提示

### 8.4 商品池机制

- 每个商店有一个商品池（goodsPool）
- 游戏开始时从池中随机选一件作为本次出售的商品
- 买完就没了，不会补货

### 8.5 关键设计

- **价格复用**：价格定义在 DropItem 基类的 price 字段里，商店直接读取
- **售罄状态**：每件商品只能买一次，避免无限刷
- **购买反馈**：有专门的购买音效和文字提示

> 架构设计详见：[PB 架构设计文档](file:///e:/unity/project/ProjectBlood/Technical%20Documentation/PB%20架构设计文档.md) 第3章「设计13：商店系统」

## 12. 加载界面系统

### 12.1 功能概述

在场景切换时显示加载过渡界面，包含动态加载文字动画和异步加载机制，提升玩家体验。

### 12.2 核心参数

| 参数                | 默认值 | 设计意图               |
| ----------------- | --- | ------------------ |
| `minDuration`     | 2秒  | 最小显示时间，避免加载过快闪烁 |
| `dotCycleTime`    | 0.4秒 | 加载文字动画切换间隔         |

### 12.3 加载流程

1. **显示加载界面**：调用 `GameUI.ShowLoadingPage(sceneName)` 显示加载页面
2. **异步加载场景**：使用 `SceneManager.LoadSceneAsync()` 在后台加载
3. **进度等待**：等待加载进度达到90%（`allowSceneActivation=false`时的进度上限）
4. **时间等待**：确保最小显示时间已过
5. **激活场景**：设置 `allowSceneActivation=true` 完成加载
6. **隐藏加载界面**：等待 `isDone` 后关闭加载页面

### 12.4 加载文字动画

加载文字循环显示四种状态，每0.4秒切换一次：
- `Loading`
- `Loading.`
- `Loading..`
- `Loading...`

### 12.5 触发时机

| 场景               | 触发方式       |
| ---------------- | ---------- |
| 游戏开始            | 点击开始按钮     |
| 关卡切换            | 接触传送门      |
| 返回主菜单           | 点击返回按钮     |

### 12.6 关键设计

- **异步加载**：使用 `allowSceneActivation=false` 实现后台加载
- **时间保护**：使用 `Time.unscaledTime` 避免 `timeScale=0` 导致的死锁
- **状态重置**：加载完成后在 `MapController.Start()` 中重置 `Global.IsGamePaused = false`

## 13. 关卡切换系统

### 13.1 功能概述

实现关卡间的无缝切换，支持多关卡配置和通关判定。

### 13.2 核心流程

**传送门触发**：
1. 玩家接触传送门 → 调用 `Portal.OnTriggerEnter2D()`
2. 调用 `MapController.instance.LoadNextLevel()`
3. 检查当前难度是否已打完全部关卡
4. **未通关**：显示加载界面 → 切换到下一关
5. **已通关**：直接显示通关结算面板

**场景切换**：
- 使用 `SceneManager.LoadScene()` 重载当前场景
- 自动清理所有动态对象（房间、敌人、传送门、掉落物、特效）

### 13.3 难度管理

| 属性              | 说明               |
| --------------- | ---------------- |
| `currentDifficulty` | 当前难度等级，从0开始 |
| `LevelConfigs.Count` | 总关卡数            |

**通关判定**：`currentDifficulty >= LevelConfigs.Count`

### 13.4 关键设计

- **场景重载**：相比手动清理对象，场景重载更可靠，避免遗漏
- **静态变量传递**：`Global.currentDifficulty` 在场景重载后保持值，用于确定当前关卡

## 14. 全局暂停状态管理

### 14.1 功能概述

统一管理游戏暂停状态，控制玩家操作权限。

### 14.2 核心属性

| 属性            | 类型      | 说明                 |
| ------------- | ------- | ------------------ |
| `IsGamePaused` | bool    | 全局暂停状态，默认false |

### 14.3 暂停状态影响

| 操作               | 暂停时状态 | 恢复时状态 |
| ---------------- | ------ | ------ |
| 射击（鼠标左键）        | 禁用     | 启用     |
| 武器切换（滚轮/Q/E/数字键） | 禁用     | 启用     |
| 换弹（R键）          | 禁用     | 启用     |
| 面板交互（空格键）      | 启用     | 启用     |

### 14.4 状态管理

| 场景面板           | 打开时    | 关闭时    |
| ---------------- | ------ | ------ |
| UIGameOverPanel  | true   | false  |
| UIGamePassPanel  | true   | false  |
| 新场景加载          | false  | -      |

### 14.5 关键设计

- **全局统一**：所有面板使用同一 `Global.IsGamePaused` 变量
- **场景重置**：`MapController.Start()` 中重置为 false，避免旧状态影响新场景

## 15. 关卡名称显示系统

### 15.1 功能概述

进入关卡时显示关卡名称（如 1-1、1-2），带有淡入淡出动画。

### 15.2 核心参数

| 参数       | 默认值 | 设计意图        |
| -------- | --- | ----------- |
| `duration` | 2秒  | 总显示时间       |
| `fadeIn`  | 0.5秒 | 淡入时长        |
| `stay`    | 1秒  | 保持显示时长      |
| `fadeOut` | 0.5秒 | 淡出时长        |

### 15.3 调用时机

`MapController.InitializeLevel()` 开始时调用 `GameUI.ShowLevelText(levelConfig.LevelName)`

### 15.4 显示效果

- 自动去除 "Level " 前缀，只显示数字部分（如 "1-1"）
- 淡入 → 保持 → 淡出的动画效果

## 16. 特效管理系统（FxManager）

### 16.1 功能概述

集中管理游戏中的特效对象（血迹、尸体、粒子效果），提供统一的清理接口。

### 16.2 核心方法

| 方法                  | 参数                     | 返回值  | 说明         |
| ------------------- | ---------------------- | ---- | ---------- |
| `SpawnEnemyBody()`  | GameObject prefab, Vector2 pos | GameObject | 生成敌人尸体   |
| `PlayEnemyHurtFX()` | Vector2 pos, Color color | void | 播放敌人受伤特效  |
| `ClearAllEffects()` | 无                      | void | 清除所有已生成特效 |

### 16.3 关键设计

- **统一管理**：所有特效通过 FxManager 创建，便于场景切换时清理
- **自动清理**：场景重载时自动销毁所有特效对象
