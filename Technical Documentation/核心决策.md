# 核心决策文档

本文档记录了项目开发过程中的重要技术决策和重构案例，旨在为开发者提供通用的学习参考资源。

***

## 1. 敌人系统设计

### 设计背景

游戏需要多种类型的敌人，但最初为每个敌人编写独立脚本会导致大量重复代码。

### 优化方案

将敌人按攻击方式分类：

- **射击型敌人**（`ShootingEnemy`）：通过参数控制子弹数量、散射角度、连发间隔
- **激光型敌人**（`LaserEnemy`）：通过参数控制充能时间、伤害频率、瞄准速度

核心状态机逻辑集中到基类，所有敌人遵循"攻击→游走→攻击"的循环，超出攻击范围时会追踪玩家。

> 详细设计见：[敌人系统设计文档](file:///e:/unity/project/ProjectBlood/Technical%20Documentation/敌人系统设计文档%20-%20美术表现与打击感.md)

## 2. 声音系统设计

### 设计背景

每个武器挂载独立的 `AudioSource` 播放音效，切换武器时音效会突然中断，影响玩家体验。

### 初始方案

武器自己管理音频播放和生命周期，导致切枪逻辑复杂，难以维护。

### 优化方案

使用集中式音频管理系统：

- 采用 QFramework 的 `AudioKit` 统一管理所有音效
- 封装到 `AudioKitManager` 单例中
- 武器只负责调用播放接口，不管理音频生命周期

### 实现效果

- 切枪时音效平滑过渡，不会突然中断
- 音量统一管理，便于调整
- 武器系统与音频系统解耦

## 3. 武器架构设计

### 设计背景

最初的 `IWeapon` 既不是真正的接口，也未有效承担父类职责，导致子类代码重复率高，职责混乱。

### 优化方案

采用双层继承架构：

- **`WeaponBase`**：处理通用逻辑（弹药管理、换弹流程、吸血特性）
- **`AutomaticWeapon`**：全自动武器基类（AK、MP5、Laser）
- **`SemiAutomaticWeapon`**：半自动武器基类（AWP、DE、ShotGun）

> 详细设计见：[武器系统设计文档 v1.0](file:///e:/unity/project/ProjectBlood/Technical%20Documentation/武器系统设计文档%20v1.0%20(2026-05-26).md)

## 4. 血库系统设计

### 设计背景

早期武器较少时采用独立弹药库设计，但随着武器数量增加，玩家管理多种弹药负担过重，违背爽快游戏体验的设计目标。

### 优化方案

引入统一血库系统：

- **共用资源池**：所有武器共享"脏血"资源，简化管理
- **软性限制**：脏血耗尽仍可射击，仅伤害降低
- **差异化消耗**：每把武器单次装填消耗不同，增加平衡维度

### 资源获取

- 玩家受伤时自动补充部分脏血
- 血库低于阈值时，击杀敌人额外获取

### 资源消耗

- 换弹时消耗脏血强化武器

### 资源转化

- 强化武器击杀敌人可回复生命值

以此构成 **生命值 → 血库 → 伤害 → 生命值** 的资源循环系统

### 设计价值

实现资源管理与爽快体验的平衡，为天赋系统提供流派差异化空间。

## 5. 纯血道具系统设计

### 设计背景

原来的吸血效果是直接给玩家加血，数值反馈很弱，玩家打了半天不知道自己回了多少血。而且缺少视觉上的爽快感，总觉得吸血就只是数字跳动一下。

### 初始方案

直接在命中时计算吸血量，然后调用 `Global.AddHP()` 加血。实现简单，但几乎没有反馈感。

### 优化方案

把吸血效果做成看得见摸得着的"纯血"道具：

- **两阶段运动**：先从敌人身上爆开飞射出去，再转个弯追踪玩家
- **数量拆分**：吸血量越大，爆出的小血球越多，视觉上更有成就感

### 实现细节

- 飞射阶段：随机方向 + 阻尼减速, 主要是为了视觉提示
- 追踪阶段：用 Lerp 平滑转向，看起来更自然
- 治疗量分配：总治疗量平摊到每个血球上，保证总和不变

### 实现效果

- 视觉反馈大大增强，多个小血球飞散再聚拢更爽
- 玩家能明显感受到"我吸到血了"

## 6. 设计原则总结

通过这些设计决策，我们总结出以下通用原则：

1. **先设计数据结构，再写逻辑** —— 合理的数据结构能大幅简化业务逻辑
2. **适度抽象** —— 平衡灵活性与复杂度，避免过度设计
3. **善用框架工具** —— 成熟的框架组件通常比自行实现更可靠
4. **单一职责** —— 每个类只负责一件事，便于维护和测试
5. **代码复用** —— 识别通用模式并抽象，减少重复代码
6. **反馈优先** —— 玩家能感知到的效果，比数值正确更重要（比如纯血道具 vs 直接加血）

## 7. 关卡切换机制设计

### 设计背景

早期关卡切换采用手动清理所有动态对象（房间、敌人、传送门、掉落物、特效）的方式，但容易遗漏，导致场景残留问题。

### 初始方案

在 `LoadNextLevel()` 中逐一调用 `Destroy()` 清理各类对象，代码冗长且不可靠。

### 优化方案

改用 **场景重载** 方式：
- 使用 `SceneManager.LoadScene()` 重载当前场景
- 利用 Unity 场景加载机制自动销毁所有场景对象
- 通过静态变量 `Global.currentDifficulty` 在场景间传递进度

### 实现效果

- 代码简洁：`LoadNextLevel()` 只需一行代码
- 清理彻底：不会遗漏任何动态对象
- 可靠性高：利用引擎原生机制，减少手动管理

## 8. 加载界面系统设计

### 设计背景

场景切换时如果加载过快，会导致玩家位置瞬间跳转，影响体验。需要一个过渡界面来提升视觉连贯性。

### 初始方案

直接加载场景，没有过渡效果，玩家体验不佳。

### 优化方案

实现异步加载 + 加载界面：
- 使用 `SceneManager.LoadSceneAsync()` 后台加载
- 设置 `allowSceneActivation=false` 暂停激活，等待加载完成
- 显示带有动画文字的加载界面
- 使用 `Time.unscaledTime` 避免 `timeScale=0` 导致的死锁

### 关键实现

```csharp
// 加载流程（协程）
asyncOp.allowSceneActivation = false;
float elapsed = 0f;
while (asyncOp.progress < 0.9f || elapsed < minDuration)
{
    LoadingText.text = loadingDots[loadingDotIndex];
    loadingDotIndex = (loadingDotIndex + 1) % loadingDots.Length;
    float dotCycleTime = 0.4f;
    float startUnscaledTime = Time.unscaledTime;
    float targetUnscaledTime = startUnscaledTime + dotCycleTime;
    while (Time.unscaledTime < targetUnscaledTime 
           && (asyncOp.progress < 0.9f || elapsed < minDuration))
    {
        elapsed += Time.unscaledDeltaTime;
        yield return null;
    }
}
asyncOp.allowSceneActivation = true;
while (!asyncOp.isDone)
{
    yield return null;
}
```

### 实现效果

- 场景切换平滑，有明显的加载过渡
- 避免玩家位置突变
- 加载文字动画增强视觉反馈

## 9. 全局暂停状态管理设计

### 设计背景

游戏结束或通关时显示结算面板，但玩家仍可操作（射击、切换武器），导致误操作。

### 初始方案

每个面板单独管理暂停状态，逻辑分散。

### 优化方案

引入统一的全局暂停状态：
- 在 `Global` 类中添加 `IsGamePaused` 静态变量
- 所有面板打开时设置为 `true`，关闭时设置为 `false`
- 玩家输入逻辑中添加 `!Global.IsGamePaused` 判断

### 关键设计

```csharp
// Player.cs 输入处理
if (Input.GetMouseButton(0) && !Global.IsGamePaused)
{
    Shoot();
}
```

### 场景重置问题

场景重载后，旧的 `GameUI` 对象被销毁，其协程无法执行重置代码，导致 `IsGamePaused` 保持为 `true`。

**解决方案**：在 `MapController.Start()` 中重置 `Global.IsGamePaused = false`

### 实现效果

- 结算面板打开时玩家无法射击或切换武器
- 场景切换后自动恢复可操作状态

## 10. 关卡名称显示设计

### 设计背景

玩家进入新关卡时，没有明显的关卡进度提示，不知道当前处于哪个关卡。

### 优化方案

添加关卡名称显示：
- 在 `GameUI` 中添加 `ShowLevelText()` 方法
- 使用协程实现淡入 → 保持 → 淡出的动画
- 自动去除 "Level " 前缀，只显示数字部分

### 实现效果

- 进入关卡时清晰显示关卡名称（如 1-1、1-2）
- 动画效果自然，不会突兀
