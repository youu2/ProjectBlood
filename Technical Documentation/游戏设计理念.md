# 游戏设计理念

> **文档状态（2026-10）**：本文记录核心玩法、数值与验证过程。标注「已实现」的内容与当前代码一致（以 `Assets/Scripts` 为准）；标注「设计稿」的内容尚未实现或仅部分实现。

## 1. 战斗资源循环

### 1.1 资源定义

| 资源 | 作用 | 状态 |
| :--- | :--- | :--- |
| 生命值 HP | 归零死亡；受伤时按伤害量转化为脏血 | 已实现 |
| 血库（脏血） | 弹药的软性限制；换弹时消耗并强化弹丸 | 已实现 |
| 武器弹药 | 伤害来源；击杀掉落脏血瓶补充血库（不治疗） | 已实现 |
| 袖剑 | 润滑资源循环；HP 与血库双低时的兜底恢复 | 已实现 |

### 1.2 循环结构

```
受伤 → HP 下降、脏血增加
     → 换弹消耗脏血 → 弹丸强化（伤害提升）
     → 强化弹击杀 → 回复 HP
```

袖剑击杀可回填脏血、回复生命并刷新自身充能，用于修补循环断裂（弹尽且低血）的状态。

### 1.3 设计意图

- 受伤本身产生资源收益，降低挫败感，鼓励激进打法。
- 弹药耗尽不强制停火，只降低伤害，避免打断高频战斗节奏。
- 资源在生存与输出之间双向转化，为流派差异提供空间。

### 1.4 风险与代价

- 系统同时耦合生命值、伤害、武器消耗、击杀回复四个变量，单点调参会影响整体收支。
- 软性限制不存在绝对资源锁，伤害衰减比例与回复速率的容错空间较小，可能出现"资源溢出碾压"或"负向循环卡壳"。
- 数值平衡成本高于传统硬限制弹药系统。

### 1.5 弹药经济与弹夹设计

**问题**：在无弹夹、开火即结算弹药的 Roguelike 射击游戏中，玩家难以预判一把新武器的**弹药经济**——即伤害 / 弹药转化率（damage-per-ammo）与弹药消耗速率（burn rate）。同时**试错成本**过高：试射一把高射速武器可能在数秒内清空资源池，而资源耗尽意味着作战能力大幅下降。结果是玩家往往带着未验证的武器进入下一关，才发现它与当前构筑不匹配。

**设计回应**：

1. **弹夹**：把弹药消耗离散化为「每弹夹一次」的可读单位。玩家在换弹时即可感知该武器的耗弹量与换弹空窗，同时在战斗中不会因持续开火意外清空资源池。
2. **软性弹药限制**：血库耗尽后仍可射击，仅伤害衰减（普通弹 / 霰弹 ×0.7，激光 / 狙击 ×0.8），避免「资源耗尽 = 能力断崖」。

**代价**：

- 换弹空窗降低持续 DPS，因此武器定位需要同时看「弹夹内 DPS」与「综合 DPS」两个口径。
- 软性限制削弱资源管理的紧张感，平衡依赖衰减比例与回复速率，调参容错低于硬性弹药。

**指标口径**：

| 指标 | 定义 |
| :--- | :--- |
| 单弹夹总伤（DPM） | 单发伤害 × 弹夹容量（霰弹按弹丸数计） |
| 弹夹内 DPS | DPM ÷ 单弹夹射击时长 |
| 综合 DPS（含换弹） | DPM ÷（单弹夹时长 + 换弹时长） |
| 伤害 / 血库消耗 | DPM ÷ 单次换弹血库消耗 |

## 4. 局内成长

### 4.1 双轨分工

| 系统 | 作用对象 | 职责 |
| :--- | :--- | :--- |
| 局内升级卡 | 基础属性、武器伤害 / 弹匣 / 攻速、技能 CD | 改数值 |
| 血印 | 触发条件、持续效果与机制 | 改规则 |

成长属性设计清单：移动速度、技能冷却、吸血率（血甲）、血甲上限、真血上限、血库上限。

### 4.2 为什么加入升级系统：可选房间的奖励梯度

**问题**：玩家已找到关卡出口、但仍有未探索房间时，会形成风险收益权衡。若剩余房间可预期为普通战斗房，且奖励仅为弹药、生命等基础资源，玩家会判断「探索的期望收益低于风险」，从而跳过内容。**玩家主动跳过内容，说明该内容的奖励结构不合格**——即使战斗本身有趣。

**设计判断**：

- 普通战斗房需要额外奖励，但必须与基础资源、高价值物品形成**奖励梯度**；不能高频、可预测地提供高光时刻，否则会稀释武器进化、血印等预设的情绪峰值。
- 升级系统提供「可预期但有随机性」的中强度成长：足以让普通房间值得探索，又不会盖过高价值奖励的反馈强度。
- 与资源循环联动：玩家不必为下一场战斗保留状态与物资，可以更主动地投入战斗，降低资源焦虑。

**奖励梯度**：

| 层级 | 来源 | 反馈强度 | 随机性 |
| :--- | :--- | :--- | :--- |
| 基础资源 | 普通战斗掉落 | 低 | 低 |
| 局内升级 | 普通战斗房 | 中 | 中 |
| 武器 / 血印 | 宝箱、商店、精英 | 高 | 高 |

### 4.3 实现约束

- 五类效果：基础属性、武器伤害、弹夹容量、攻速、技能 CD。
- 按卡独立计数：`MaxUpgradeCount` 作用于单张卡，多张影响同一属性的卡互不影响。
- 整卡排除：组合效果采用「全有或全无」的可用性判定，避免出现半生效卡片。
- 抽取过滤：未持有武器、未加载技能对应的条目不会进入卡池。

**风险**：升级卡会稀释单局构筑的稀有度，需要通过卡池容量、每卡可选次数与可用性过滤控制强度。

## 5. Boss 设计（已实现）

**实现位置**：`TitanBoss.cs`（状态机与攻击）、`BossBase.cs`（阶段切换、血条、掉落、传送门）。

**形象**：Titan

**武器**：双管霰弹枪，弹夹 2 发，每次攻击快速射击两次。

### 5.1 行为状态

| 状态 | 行为 | 关键参数 |
| :--- | :--- | :--- |
| Idle | 原地等待；房间进入 Battle 后转为追踪 | — |
| Chase | 沿 A* 路径追击；进入攻击距离且视线可见时开火 | 移速 2.0 |
| Attack | **站定**双发射击；结束后进入换弹 | 两发间隔 0.8s，攻击距离 10 |
| Reload | 原地换弹；结束后回到追踪 | 2.0s |
| PhaseTransition | 生命值降至 50% 时打断当前动作，原地变红演出并喷射 PureBlood | 1.0s |
| AngryChase | 更快追击；满足距离与冷却时选择攻击、爆发推进或环形射击 | 移速 3.5 |
| AngryAttack | **站定**双发射击；结束后进入愤怒换弹 | 两发间隔 0.3s |
| AngryReload | 原地换弹；结束后按距离与冷却选择环形射击、爆发推进或继续追击 | 1.5s |
| Dash | 向玩家直线突进；结束后立即接一次愤怒双发 | 8s CD、速度 12、持续 0.4s |
| RingShot | 以自身为中心射出 3 圈子弹；结束后进入愤怒换弹 | 10s CD、每圈 16 发、圈间隔 0.8s |

### 5.2 实现要点

- 视线判定使用射线检测，仅在一阶段/二阶段追踪状态执行，间隔 0.3s。
- 武器朝向按 `rotationSpeed`（默认 180°/s）逐步转向玩家，而非瞬间锁敌，玩家可通过走位甩开枪口。
- 散射与环形弹幕复用 `EnemyBase.FireScatterBullets`；追击复用基类 A* 寻路。
- 二阶段开始时停止所有协程、播放 1 秒变红演出，结束后进入环形射击；转阶段通过 `phaseTwoHpPercent` 控制。
- Boss 不可被袖剑处决；死亡后掉落金币与脏血并激活传送门。

## 6. 设计验证：轮切 DPS

### 6.1 测试方法

- 目标：10000 HP 木桩，近距离。
- 操作：快速来回滚动滚轮切枪，持续输出至击杀，记录用时。
- 前提：武器获取顺序固定，1 把半自动与 1 把全自动交替获得。
- 局限：DPS 受切枪频率与命中率影响，结果存在波动；各组总弹夹容量不同，未做归一化。

### 6.2 原始数据

| 配置 | 半自动/全自动 | 击杀时间 | DPS | 相对上一档 |
| :--- | :--- | :--- | :--- | :--- |
| DE + MP5 | 1 / 1 | 83s | 120.5 | — |
| + ShotGun | 2 / 1 | 45s | 222.2 | +84.4% |
| + AK | 2 / 2 | 42s | 238.1 | +7.1% |
| + AWP | 3 / 2 | 24s | 416.7 | +75.0% |
| + Laser | 3 / 3 | 22s | 454.5 | +9.1% |

### 6.3 边际分析

| 新增武器 | 类型 | 边际 DPS 增量 | 单持 DPS（表 2） |
| :--- | :--- | :--- | :--- |
| ShotGun | 半自动 | +101.7 | 150 |
| AK | 全自动 | +15.9 | 129.3 |
| AWP | 半自动 | +178.6 | 83.3 |
| Laser | 全自动 | +37.9 | 70.6 |

单持 DPS 相近的两组对照：

- ShotGun / AK：单持 150 vs 129.3，轮切边际贡献 **6.4 倍**。
- AWP / Laser：单持 83.3 vs 70.6，轮切边际贡献 **4.7 倍**。

### 6.4 结论

- 每加入 1 把半自动，DPS 提升 75~84%；每加入 1 把全自动，仅提升 7~9%。
- 单持 DPS 相近时，轮切贡献差异仍达 4.7~6.4 倍，说明收益来自**射击间隔被切枪重置**，而非单发伤害或弹夹容量。
- 因此强化池对半自动只投放攻速与弹匣，不投放增伤；增伤留给全自动。否则增伤会被切枪频率成倍兑现，Boss 数值不可控。
- 仅提高半自动射速不会显著增加轮切 DPS（间隔本就被重置），但能改善单持清怪手感。

### 6.5 数据边界

- 固定获取顺序下，半自动数、全自动数与武器总数同步增长，三者在原始数据中共线，无法直接分离。
- 当前用"单持 DPS 相近的武器配对"做间接验证；严格验证需关闭 `SwitchFromSet` 中的 `attackInterval.Reset()` 做同配置 A/B，尚未执行。
- 后续可通过限制半自动弹夹容量成长上限，降低单轮总伤与血库续航，进一步压低实战击杀速度。
